1. **Achieving the impossible: XSS in innerHTML without equals** — PortSwigger Research, 18 Nov 2026.
   <https://portswigger.net/research/achieving-the-impossible-xss-in-innerhtml-without-equals>
   Technique: in an `innerHTML` sink where `=`, `/` and whitespace are all stripped, a `<select><selectedcontent>` clones the selected `<option>`'s children using the same deep-clone algorithm as `cloneNode(true)`; some engines don't flag an SVG `<script>` built via `innerHTML` as "already started", so the clone executes it. No attributes or `=` needed since the first `<option>` is selected by default.
   Skill: `hunt-xss` (new bypass under "Bypass Techniques" / sanitizer bypasses). **Applied.**

2. **Blind trust: stealing credentials through CSP** — PortSwigger Research, 11 Nov 2026.
   <https://portswigger.net/research/blind-trust-stealing-credentials-through-csp>
   Technique: HTML injection behind a strict CSP (`default-src 'none'`) can still exfiltrate credentials with zero JS when `form-action` is missing/`'self'`. An injected self-posting fake-login form pushes credentials + a second-stage payload into the URL query string; the page reflects that parameter unescaped, letting a `<meta http-equiv=refresh>` navigation leak the full URL (and thus the credentials) via the `Referer` header to an attacker host. No script execution required, so `script-src`/`strict-dynamic` are irrelevant.
   Skill: `hunt-html-injection` (new section: CSP-constrained injection, no-JS credential exfil). **Applied.** Cross-referenced from `hunt-xss`'s existing CSP-bypass bullet list (script-gadget route is the complementary case where `script-src` itself is permissive).

3. **Making HTTP header injection critical with one prompt** — PortSwigger Research, 4 Nov 2026.
   <https://portswigger.net/research/making-http-header-injection-critical-with-one-prompt>
   Technique: a phased methodology for walking a bare CRLF header-injection point up to a full request-smuggling desync: (1) locate where in the forwarded request the injected header lands relative to the upstream `Host` header via status-code diffing, (2) validate the desync with CL/TE-style prefix fuzzing from that position, (3) find an open-redirect gadget keyed off `Host`/`X-Forwarded-Host` to make impact demonstrable, (4) chain and confirm cross-client effect. Falls back to blind request tunnelling if a full desync can't be proven.
   Skill: `hunt-http-smuggling` (new section: escalation workflow for header-injection-reached desyncs). **Applied.**
