## Examined

1. **Achieving the impossible: XSS in innerHTML without equals** — PortSwigger
   Research (Masato Kinugawa, published 18 Nov 2026).
   <https://portswigger.net/research/achieving-the-impossible-xss-in-innerhtml-without-equals>
   Technique: a `<select>`/`<option>`/`<selectedcontent>` structure clones an
   `<option>`'s children via the same algorithm as `cloneNode(true)`. On the affected
   engine, a cloned `<svg><script>` ran despite being inserted via `innerHTML`,
   because the "already started" flag stayed `false` for SVG-namespace scripts
   produced this way (unlike HTML `<script>`, which the spec marks already-started).
   No `=` character needed anywhere in the payload — defeats filters that strip `=`
   to kill attribute-based handlers.
   **Skill: `hunt-xss`. Applied** — added to the "Sanitizer Bypasses" list under
   Bypass Techniques, with the browser-dependency caveat and source link.

2. **Blind trust: stealing credentials through CSP** — PortSwigger Research
   (Gareth Heyes, published 11 Nov 2026, updated 16 Nov 2026; notes an independent
   finding of the same technique by Rafał Wójcicki / AFINE).
   <https://portswigger.net/research/blind-trust-stealing-credentials-through-csp>
   Technique: an HTML-injection point (not XSS — no script runs) is used to plant a
   self-submitting `<form>` with username/password fields plus a second-stage
   payload field. On submit, the credentials land in the query string and get
   reflected again; the second-stage payload is `<meta name="referrer" content="unsafe-url">`
   + `<meta http-equiv="refresh">`, which forces a navigation that leaks the full
   URL (credentials included) in the `Referer` header to an attacker host. Works
   under a CSP that blocks all scripts, because `form-action` does not inherit from
   `default-src` and is commonly left unset or `'self'` (which still permits the
   self-submitting form).
   **Skill: `hunt-html-injection`. Applied** — added a new "CSP-proof credential
   theft via injected form + meta-refresh" section with the four-step mechanism,
   detection signal (missing/weak `form-action` + unescaped reflection), and fix
   verification note (enforcing header, not report-only). Cross-referenced
   `hunt-ato`, `hunt-cors`/`hunt-open-redirect`.

3. **Making HTTP header injection critical with one prompt** — PortSwigger
   Research (Tom Stacey, published 4 Nov 2026, updated 11 Nov 2026).
   <https://portswigger.net/research/making-http-header-injection-critical-with-one-prompt>
   Technique: a four-phase methodology that escalates a plain HTTP header-injection
   point into a CRLF-powered desync and then a cross-victim redirect — (1) locate
   where in the upstream request the injected header lands (diff response to a CRLF
   payload vs. one that also injects a second `Host` header), (2) validate desync by
   fuzzing prefixes and looking for 2–3 distinct status codes across identical
   requests, (3) crawl for a redirect gadget that trusts `Host`/`X-Forwarded-Host`/an
   absolute-URL request line, (4) combine phases 2+3 so the smuggled request
   triggers the gadget against other users' connections. Explicitly avoids Response
   Queue Poisoning as too high-collateral for live validation.
   **Skill: `hunt-http-smuggling`. Applied** — added a "From plain header injection
   to desync (four-phase methodology)" section, with the fallback note (a validated
   desync without a gadget is still reportable) and cross-references to
   `hunt-open-redirect` and `hunt-cache-poison`.
